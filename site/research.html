01 The problem

Why an intrusion detector benefits from fewer, better features.

An intrusion detection system inspects every network connection and decides whether it is normal or an attack. NSL-KDD describes each connection with 41 features: basic header fields, payload content indicators, and traffic statistics over the last two seconds and the last 100 connections to the same host.

More features is not automatically better. Many of them are near-duplicates of each other, some never vary, and every extra feature slows the detector and gives a distance-based classifier like KNN more noise to get lost in. Feature selection asks: which small subset keeps (or improves) detection? With 41 features there are 241 ≈ 2.2 trillion subsets, far too many to try, which is where a search heuristic like HHO comes in.

02 The algorithm

Escaping energy, four besiege strategies, Lévy dives, and binary transfer functions.

Harris hawks hunt cooperatively: the family perches and scouts, and once a rabbit is spotted they encircle it and take turns diving until it is exhausted. Heidari et al. (2019) turned this into an optimizer. Each hawk is a candidate solution; the rabbit is the best solution found so far. A single number, the rabbit's escaping energy E, decides how every hawk moves.

Lévy flight vs random walk

Same number of steps, same random directions. Lévy step lengths have a heavy tail: mostly tiny moves around one spot, with an occasional long jump to a new region. HHO's rapid dives use them so a hawk that is stuck near the rabbit can still leap out of a local optimum.

From positions to feature bits

S(x) = 1/(1+e−x) V(x) = |tanh x|
S-shaped: P(bit = 1) = → /41 on
V-shaped: P(flip) = → flips

HHO moves hawks through continuous space, but a feature is either in or out. The S-shaped function treats a position as the probability of a 1; the V-shaped one, applied to the step size, flips bits only when a hawk actually moves, so the search can settle as the besiege tightens.
